# Printer support matrix

Research date: **2026-09-26**. Scope: every printer family Nozzle It All connects to or exports for, across Android,
Desktop and Web. Every external claim carries a source key (`[S#]`, listed at the end). Local claims cite the file in this
repository. "Unknown" means no official source was found; nothing here is inferred from a protocol guess.

Status words:
- **EXISTING**: implemented in that client today. **PARTIAL**: implemented with named gaps. **MISSING**: not implemented.
- **VERIFIED**: run on real hardware of that family (per `docs/WORK_ORDER.md` and the owner: only generic
  Klipper/Moonraker, Snapmaker U1 on PAXX firmware, and Elegoo Centauri Carbon on OpenCentauri COSMOS).
  **UNVERIFIED**: built from vendor documentation and tested, at most, against an emulator or a test server.

Where things live today:
- Android: all transport clients in `transport/src/main/kotlin/net/jamesjennison/klippercompanion/` (Moonraker, OctoPrint,
  PrusaLink, Bambu MQTT/FTPS/camera, scanner) and `domain/.../PrinterCapabilities.kt` (`capabilitiesFor(PrinterKind)`).
- Desktop: `adapter-paxx/` (`PaxxLanAdapter`, `MoonrakerLan`, `U1Protocol`) and the optional `stock-u1-adapter/`.
- Web: `web/src/printers/paxx.ts` (Moonraker from the browser) and `web/src/printers/connector.ts` (local connector on
  `127.0.0.1:47321`, served by Desktop).
- Slicing profiles: `app/src/main/assets/slicer_profiles/` holds **376 flattened packs from 60 vendors**
  (machine/process/filament JSON each), generated by `scripts/bundle_vendor_profiles.py` from the vendored OrcaSlicer
  checkout pinned in `engine/ENGINE_PIN.json` (SoftFever/OrcaSlicer `824b216f18232a0e25644e225c286746ee07cb5f`,
  committed 2026-09-21). OrcaSlicer's repository licence is AGPL-3.0 [S30]; `resources/profiles/` in that checkout has
  **no per-vendor LICENSE, COPYING or licence field** (checked locally). None of the 371 generated packs has been run on
  a real printer of its model (`slicer_profiles/PROVENANCE.md`).

## 1. Snapmaker U1 on PAXX Extended Firmware (flagship)

- **Models**: Snapmaker U1 (4-toolhead toolchanger) with paxx12's Extended Firmware [S1][S2].
- **Firmware project**: independent, not affiliated with Snapmaker; GPL-3.0 [S2]. Adds SSH, Fluidd/Mainsail choice,
  WebRTC/RTSP camera streaming, Spoolman with RFID (OpenSpool, Bambu, Creality tags), Tailscale and cloud remote-access
  options, timelapse, AFC-Lite UI, config UI at `http://<printer>/firmware-config` [S1][S2].
- **Profiles**: `snapmaker_u1` pack (OrcaSlicer vendor `Snapmaker` 02.04.00.15), "Snapmaker U1 (0.4 nozzle)" /
  "0.20 Standard" / "Snapmaker PLA @U1". Licence: OrcaSlicer repo AGPL-3.0 only; no vendor-specific statement.
- **Output**: plain Klipper-flavour `.gcode` (Moonraker upload).
- **Discovery**: Android `PrinterScanner` TCP sweep of ports 7125/80 verified by `GET /server/info`. Moonraker's
  `[zeroconf]` component supports mDNS and SSDP [S13][S14]; Nozzle does not browse mDNS today.
- **Auth**: Moonraker `X-Api-Key`, JWT login, trusted clients; one-shot token for WebSocket [S11][S12]. PAXX default
  is trusted-LAN (no key); Nozzle sends a key only when configured (`Moonraker.kt`).
- **Upload / control**: `POST /server/files/upload`, `printer/print/start|pause|resume|cancel`, G-code scripts, macros,
  jog, bed mesh, timelapse render (`Moonraker.kt`, `PrinterCapabilities.kt`).
- **Cameras**: `/server/webcams/list`, MJPEG/snapshot URLs (`Moonraker.kt`); PAXX also offers WebRTC and RTSP [S1].
- **Materials / multi-material**: `print_task_config` (filament_exist/vendor/type/colour per toolhead, see
  `web/src/printers/paxx.ts` `STATUS_QUERY`), extruder0-3, multiACE (PAXX add-on, `hasMultiAce = true`), Spoolman via
  `server/spoolman/*`.
- **Vendor cloud**: none needed. Remote: private network (Tailscale per [S1]); PAXX also documents a cloud option [S1].
- **Nozzle today**: Android EXISTING; Desktop EXISTING (`adapter-paxx`); Web EXISTING (direct HTTP or connector).
- **Browser feasibility**: direct HTTP only when Moonraker `cors_domains` includes Nozzle's origin [S11] and the browser
  permits the HTTPS-page to local-HTTP request (Chrome Local Network Access prompt, `targetAddressSpace` [S31]);
  otherwise the local connector. WebSocket needs a one-shot token when a key is set [S12].
- **Hardware**: **VERIFIED** (owner's PAXX U1; `WORK_ORDER.md` line ~1548 manual pass on a real U1). Open: no physical
  multi-tool print carried through (`WORK_ORDER.md` ~437, ~2459).

## 2. Snapmaker U1, stock firmware

- **Models**: Snapmaker U1, stock firmware. Stack is Snapmaker forks of Klipper and Moonraker, both GPL-3.0 [S3][S4].
- **Profiles**: same `snapmaker_u1` pack. Snapmaker's own slicer is "Snapmaker Orca" (an OrcaSlicer fork) [S6].
- **Output**: `.gcode` over Moonraker (port 7125 reported by third-party toolkit [S7]; LAN send confirmed by [S5]).
- **Discovery**: stock uses mDNS plus PIN pairing inside Snapmaker Orca's Flutter layer
  (`docs/family/STOCK_U1_DEPENDENCY_AUDIT.md` §5). Snapmaker wiki: bind "by IP address or by searching" [S5].
- **Auth**: LAN mode must be enabled on the printer (Settings > LAN Mode) [S5]; Moonraker auth details on stock:
  **unknown** from official docs. Bespok3d enrollment (port 4269, SSH) is a separate Android-only add-on
  (`Bespok3dU1Enrollment.kt`).
- **Upload / control / camera / materials**: same Moonraker surface as §1 minus multiACE (PAXX-only);
  `print_task_config` + `FILAMENT_DT_*` work on stock; editing a tag-read spool needs PAXX `FORCE=1` (audit §4 table).
- **Vendor cloud**: needed only for account sign-in, cloud binding/device list, WAN status/control, cloud print and WAN
  timelapse export (audit §5). Everything else has a LAN route.
- **Nozzle today**: Android EXISTING (`PrinterKind.SNAPMAKER_U1`, with Bespok3d); Desktop PARTIAL (optional
  `stock-u1-adapter`, includes `SnapmakerAccount.kt`); Web PARTIAL (Moonraker path shared with PAXX; no cloud).
- **Browser feasibility**: as §1 for LAN; Snapmaker cloud from a browser: **unknown** (no public API docs found).
- **Hardware**: **UNVERIFIED** (`verifiedOnRealHardware = false`; owner's U1 runs PAXX).

## 3. Generic Klipper / Moonraker (incl. Elegoo Centauri Carbon on OpenCentauri COSMOS)

- **Models**: any Klipper + Moonraker printer (Voron, RatRig, Creality/Sovol/Qidi Klipper models, etc.).
  Elegoo Centauri Carbon is supported only on OpenCentauri COSMOS firmware [S29].
- **Profiles**: `generic_klipper` (OrcaSlicer "MyKlipper" template), plus per-model packs (Voron 8, RatRig 21, Creality 57,
  Qidi 12, Sovol 13, ...). `elegoo_centauri_carbon_cosmos` = OrcaSlicer "Elegoo Centauri Carbon 0.4 nozzle" (vendor
  `Elegoo` 02.04.00.09) **plus** a G-code overlay from OrcaSlicer Cloud bundle `3fad3c38f25f` (user `mudkip`, v0.07),
  linked from OpenCentauri's install docs [S29]. The stock Elegoo pack is deliberately excluded (`PROVENANCE.md`).
- **Output**: `.gcode`.
- **Discovery**: Moonraker `[zeroconf]` (mDNS hostname, optional SSDP) [S13][S14]; Nozzle: TCP sweep only.
- **Auth**: API key / JWT / trusted clients / one-shot token [S11][S12].
- **Upload / control**: full, as §1. **Files, history** (`server/history/list`), console (`server/gcode_store`), LEDs,
  timelapse (moonraker-timelapse), update_manager exists server-side [S10] but Nozzle does not drive it.
- **Cameras**: `[webcam]` config (`service`, `stream_url`, `snapshot_url`, flips/rotation) [S10] via
  `server/webcams/list`.
- **Materials / multi-material**: Spoolman via Moonraker `[spoolman]` proxy (Nozzle EXISTING, `spoolmanInventory()`);
  Happy Hare [S15] and AFC [S16] expose their own Klipper objects: Nozzle reads **neither** today (MISSING).
- **Vendor cloud**: none. Remote: private network/VPN; Moonraker has no vendor relay.
- **Nozzle today**: Android EXISTING; Desktop PARTIAL (`MoonrakerLan` shared "PAXX and generic Moonraker" reads; no
  generic-Klipper panels); Web PARTIAL (same Moonraker code path as PAXX; U1-specific fields absent).
- **Browser feasibility**: HTTP + WebSocket feasible with `cors_domains` [S11] and LNA permission [S31]; else connector.
- **Hardware**: **VERIFIED** for generic Klipper/Moonraker and Centauri Carbon COSMOS (owner). COSMOS caveat: only the
  26.07.0+ profile generation is bundled; legacy firmware reports `Mismatch` (`PROVENANCE.md`, `FirmwareIdentity.kt`).

## 4. Bambu Lab (X1/X1C/X1E, P1P/P1S, P2S, A1/A1 mini, H2D/H2D Pro/H2S/H2C, X2D)

- **Models with bundled packs (13)**: A1 (`bambu_generic`), A1 mini, P1P, P1S, P2S, X1, X1 Carbon, X1E, H2D, H2D Pro,
  H2S, H2C, X2D. Skipped: A2L (engine cannot slice its G-code templates, `PROVENANCE.md`).
- **Profiles**: OrcaSlicer vendor `BBL` version 02.01.00.28, `url: http://www.bambulab.com/Parameters/vendor/BBL.json`.
  Origin is Bambu Studio's profile set (Bambu Studio is AGPL-3.0 [S32]); inside OrcaSlicer there is no separate licence
  statement. **Flag**: licence inherited by repository location only; filament names use Bambu trademarks.
- **Output**: `.gcode.3mf` bundle (Nozzle builds it on Android via `engine::slice_bambu_bundle`; `BambuPrintProtocol.kt`
  rejects anything else).
- **Discovery**: SSDP multicast `239.255.255.250`, ports 1990/2021, ST `urn:bambulab-com:device:3dprinter:1`
  (`PrinterScanner.kt`, verified against the fakebambu emulator, `WORK_ORDER.md` WO-37). Official Bambu doc for SSDP:
  **unknown** (wiki not retrievable, HTTP 402).
- **Access modes**: Authorization Control (Jan 2025) blocks third-party write actions in cloud mode; **LAN-only mode +
  Developer Mode** leaves MQTT, FTP and live stream open without authorization [S8][S9]. Sanctioned cloud-mode route
  for third parties is Bambu Connect [S8]. Developer Mode minimum firmware (third-party helpdesk, not Bambu): X1
  01.08.03.00, P1 01.08.02.00, A1 01.05.00.00, H2D 01.01.00.01, P2 series shipped enabled [S9]; H2S/H2C/X2D: **unknown**.
- **Auth**: MQTT over TLS 8883, user `bblp`, password = access code; topics `device/<serial>/report|request`
  (`BambuMqttConnection.kt`). Self-signed "BBL CA" chain; Nozzle pins per-serial SHA-256 on first use and requires the
  leaf CN = serial (`BambuTrust.kt`).
- **Upload**: implicit-TLS FTPS on 990, user `bblp` (`BambuFtpsClient.kt`), then MQTT `project_file` print command.
- **Control**: pause/resume/stop over MQTT (`BambuPrinterService.kt`). Temperatures/motion over MQTT are possible in
  Developer Mode [S8][S9]; Nozzle does not send them.
- **Cameras**: RTSPS 322 (`rtsps://bblp:<code>@<ip>:322/streaming/live/1`) on X1/X1C/X1E/X2D/P2S/H2C/H2D/H2D Pro/H2S;
  proprietary JPEG stream on 6000 on A1/A1 mini/P1P/P1S [S17][S18]; LAN Liveview must be on [S17]. One report says
  X2D uses a different "BRTC" stream, not RTSP [S19] (conflicts with [S18]: treat X2D camera as **unknown**).
  **Nozzle implements only the port-6000 path** (`BambuChamberCamera.kt`, re-served as MJPEG on loopback):
  X1/H2/P2S cameras are MISSING.
- **Materials / multi-material**: AMS state arrives in the MQTT report [S9]; Nozzle drops AMS mapping (single-material,
  external spool only: `BambuPrintProtocol.kt`, `BambuPrintPanel.kt`, `WORK_ORDER.md` ~2460). MISSING.
- **Vendor cloud**: needed for Bambu Handy / cloud printing / remote access in cloud mode; LAN-only disables Handy [S9].
  Firmware updates in LAN-only: offline firmware packages are published per model [S20] (update procedure not verified here).
- **Remote access**: LAN mode has no relay; private network/VPN reaching the printer's LAN is the only non-cloud route.
- **Nozzle today**: Android PARTIAL (status, pause/resume/stop, upload+print, A1/P1 camera); Desktop MISSING; Web MISSING.
- **Browser feasibility**: **impossible directly** (browsers cannot open raw MQTT/TLS, FTPS or RTSPS sockets, and the
  printer's certificate is not publicly trusted). Local connector only.
- **Hardware**: **UNVERIFIED** (emulator only; `project_file` acknowledgement path unverified, WO-37).

## 5. Prusa (MK4/MK4S, MK3.9/MK3.5, MINI/MINI+, XL, CORE One/One L, MK3S)

- **Models with bundled packs (10)**: MK4 (`prusa_generic`), MK4S, MK3.5, MK3S, MINI, MINI IS, XL, XL 5T, CORE One,
  CORE One L. **No MK3.9 pack** (MK3.5 is the nearest; do not assume equivalence).
- **Profiles**: OrcaSlicer vendor `Prusa` 02.04.00.06, no licence field. Prusa's own profile repository
  `PrusaSlicer-settings-prusa-fff` has **no LICENSE file**; licence question issue #36 (2026-01-27) is open with no
  official answer [S21]. **Flag**: licence unclear.
- **Output**: `.gcode` (Nozzle sends plain G-code). **`.bgcode`: not emitted**. OrcaSlicer has no binary G-code option
  (feature request #3564 open [S22]; `binary_gcode` absent from pinned `PrintConfig.cpp`, checked locally); community
  post-processor `orca_bgcode` exists [S23]. PrusaSlicer's printer-level "Supports binary G-code" [S22] has no Orca
  equivalent.
- **Local API**: PrusaLink on Buddy firmware (MINI/MINI+, MK3.9/MK4/MK4S, XL, CORE One; FW >= 4.7.0 for v1 API) [S24];
  on MK2.5/MK3/MK3S(+) via Raspberry Pi PrusaLink [S26]. OpenAPI spec `spec/openapi.yaml`, GPL-3.0 repo [S25][S27].
- **Discovery**: Nozzle probes `GET /api/version` on port 80. mDNS hostname answers exist on Buddy (bug report [S28]);
  DNS-SD service advertisement: **unknown** (feature request open [S28b]).
- **Auth**: HTTP Digest for `/api/v1` [S27]; Nozzle hard-codes username `maker` (`PrusaLinkPrinterService.kt`), the
  Buddy default. **Flag**: RPi PrusaLink users set their own username in its wizard [S26]: likely mismatch.
- **Upload / control**: `PUT /api/v1/files/{storage}/{path}` with `Print-After-Upload`; job pause/resume/stop via
  `/api/v1/job/{id}`; storage resolved from `GET /api/v1/storage` [S27] (all EXISTING on Android). Files: top-level only.
- **Cameras**: spec has `/api/v1/cameras` and `/cameras/{id}/snap` [S27]; Buddy3D camera pairs through Prusa Connect or
  the Prusa app [S33]; LAN-only camera setup is requested by users, not documented [S33]. Nozzle: MISSING.
- **Materials / multi-material**: XL tool count and MMU3 state via PrusaLink: **unknown** (not in the v1 status schema
  summary [S27]). XL 5T slicing pack exists (5 nozzles) but no physical multi-tool print (`WORK_ORDER.md` ~2375, ~2459).
- **Vendor cloud**: Prusa Connect: remote control and camera relay [S24][S34]; local PrusaLink covers print control.
- **Nozzle today**: Android PARTIAL; Desktop MISSING; Web MISSING.
- **Browser feasibility**: HTTP is possible only if PrusaLink sends CORS headers **and** the browser handles Digest on
  cross-origin requests; PrusaLink CORS is **unverified** (`WORK_ORDER.md` ~2322). Plan for the connector.
- **Hardware**: **UNVERIFIED** (no owner hardware; documentation tier only).

## 6. OctoPrint

- **Models**: any printer OctoPrint drives over serial (profiles: whatever the printer's own pack is).
- **Output**: `.gcode` (Nozzle's upload regex accepts `.gcode|.gco|.g`). OctoPrint blocks `.bgcode` without a plugin [S35].
- **Discovery**: bundled Discovery plugin: zeroconf `_octoprint._tcp` and `_http._tcp`, SSDP/UPnP [S36]. Nozzle: TCP
  sweep of 5000/80 and page fingerprint.
- **Auth**: `X-Api-Key`, `Authorization: Bearer`, or `?apikey=` [S37]; Application Keys workflow
  (`/plugin/appkeys/probe`, `request`, poll, decision) [S38]. Nozzle: manual key entry; appkeys flow MISSING.
- **Upload / control**: `POST /api/files/local` multipart `select`/`print`, `/api/job` pause/resume/cancel
  (`OctoPrintPrinterService.kt`); `effectivePrint=false` surfaced as an error.
- **Cameras**: OctoPrint webcam settings exist; Nozzle: MISSING (`supportsCamera = false`).
- **Materials**: none native; plugin-dependent (**unknown**).
- **Vendor cloud**: none. Remote: VPN or third-party plugins.
- **Nozzle today**: Android EXISTING (scoped); Desktop MISSING; Web MISSING.
- **Browser feasibility**: needs `api.allowCrossOrigin: true`; cookies are not sent cross-origin so an API key is
  mandatory [S37]; plus LNA [S31].
- **Hardware**: **UNVERIFIED** (real OctoPrint 1.11 server with virtual printer only, `OctoPrintPrinterService.kt`).

## 7. Export-only targets (every bundled model without a connector)

- **Scope**: all 376 packs can be sliced; those whose firmware Nozzle cannot talk to are export-only (SD card, USB, or
  the vendor's own app). Examples: Creality 57 (non-Klipper models), Anycubic 20, Flashforge 13, Artillery 10, Wanhao 19,
  Volumic 25, Snapmaker A-series/J1/Artisan 18, Ultimaker 2, and ~50 others.
- **Formats Nozzle can emit**: `.gcode` (all), `.gcode.3mf` (Bambu only). **Not**: `.bgcode` [S22], UltiMaker `.ufp`
  (unknown; not implemented), Flashforge/other proprietary containers (unknown).
- **Licence**: OrcaSlicer AGPL-3.0 repository licence only; no per-vendor statements in the checkout.
- **Hardware**: all **UNVERIFIED** (`PROVENANCE.md`: "Profile only").

## Licence and provenance gaps in bundled profiles

1. **Prusa packs (10)**: upstream `PrusaSlicer-settings-prusa-fff` has no LICENSE; issue #36 unanswered [S21]. OrcaSlicer
   copies carry only the repo-level AGPL-3.0. Needs a written position before redistribution is called "clean".
2. **Bambu packs (13)**: derived from Bambu Studio (AGPL-3.0 [S32]), vendor file points at bambulab.com; no explicit
   licence in the profile tree. Filament/brand names are Bambu trademarks; keep the site's trademark disclaimer.
3. **COSMOS overlay**: taken from an OrcaSlicer Cloud user bundle (`mudkip`, `3fad3c38f25f`, v0.07); its licence is
   **unknown**. Trusted for correctness because OpenCentauri links it [S29], not because a licence was granted.
4. **All 60 vendors**: `resources/profiles/` has no per-vendor licence or copyright markings (checked at the pinned
   commit); every pack relies on OrcaSlicer's repository-level AGPL-3.0 [S30]. No per-vendor upstream (e.g. vendor-
   maintained profile repos) has been traced.
5. **Provenance record**: `PROVENANCE.md` names the OrcaSlicer checkout date (2026-09-21) but not the commit; it should
   quote `824b216f18232a0e25644e225c286746ee07cb5f` and the per-vendor bundle versions (e.g. BBL 02.01.00.28, Prusa
   02.04.00.06, Snapmaker 02.04.00.15, Elegoo 02.04.00.09, Voron 02.04.00.03, Creality 02.03.02.84).
6. **Generator edits**: `bundle_vendor_profiles.py` appends `G92 E0` and changes `curr_bed_type` for some packs
   (`PROVENANCE.md` 2026-09-26): modified AGPL files must be marked as modified.
7. **Coverage gaps, not licence**: no MK3.9 pack; Bambu A2L and CONSTRUCT3D Construct 1 skipped; legacy COSMOS profile
   generation not bundled.

## Findings that need code follow-up (not changed here)

- Bambu X1/X2D/P2S/H2-series camera (RTSPS 322) is not implemented; the public site says "the chamber camera" without
  that restriction (`site-src/pages/printers.html`).
- PrusaLink username hard-coded to `maker`; wrong for Raspberry-Pi PrusaLink (MK3S) where the user chooses it [S26].
- PrusaLink camera endpoints exist in the spec [S27] but Nozzle reports "No camera".
- `.bgcode` is not producible; Prusa printers accept plain `.gcode`, so this is a speed/size gap, not a blocker.
