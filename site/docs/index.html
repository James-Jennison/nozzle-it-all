Docs

These steps describe the Android app as it is being built. It is in invite-only closed testing on Google Play and not yet publicly available (see Platforms), so screens and names may change. The web app and desktop apps do not exist yet, so nothing here applies to them.

1. Add a printer

  1. Open the app and choose Add printer. On a fresh install it opens for you after a short welcome.
  2. Press Scan network to find printers on your Wi-Fi, or pick the type and type the address yourself. The phone and printer must be on the same network.
  3. Fill in what your printer type needs:
    • Klipper / Snapmaker U1: the printer's address. An API key is optional.
    • Bambu Lab: the printer's IP address, serial number and access code, all shown in its own network settings. LAN mode must be on.
    • OctoPrint: its address and an API key, created in OctoPrint under Settings, Application Keys.
    • PrusaLink: the printer's address and its PrusaLink password.
  4. Optionally pick the bundled slicing profile for the printer. Some printers ask you to confirm their firmware first.
  5. The app tests the connection. When it passes, press Finish.

Away from home

A printer's local address only works on its own network. To reach it from elsewhere, put it behind one of these, then enter that address in the app. The app has this list built in (Add printer, "Connecting away from home"). The app never routes your printer's traffic through a server of ours; it just connects to the address you enter.

  • Tailscale (the one we suggest). Install Tailscale on the machine that runs the printer's software and on your phone, then use the 100.x.x.x address or *.ts.net name it gives you. There is nothing to set up on your router, and traffic is encrypted between your own devices. The app accepts that address over plain http:// because it stays inside your private Tailscale network.
  • Cloudflare Tunnel. A free "Quick Tunnel" gives the printer a public https:// address without opening a port on your router. Cloudflare's servers carry the traffic and can see it.
  • OctoEverywhere. A third-party relay with a free tier and no router setup. Your access depends on their service, and their servers carry the traffic.
  • Port forwarding. Forward a port on your router and use a dynamic DNS name if your address changes. No third party is involved, but the printer is exposed to the internet, so use an API key and https://.

Whichever you pick, an API key is the only thing standing between your printer and anyone who reaches that address, so set one for anything other than Tailscale. See the privacy policy for what each option means for your data.

2. Slice a model and send it

  1. In the Files tab, open Projects and start a new project, then add a model file (STL, 3MF or OBJ). You can also share a model file to Nozzle It All from another app, or start one from Discover.
  2. Place and adjust it on the 3D plate. The app warns you if it does not fit the printer's bed.
  3. Choose the quality, infill and supports, then slice. Slicing happens on your phone.
  4. Check the layer-by-layer preview and the estimated time and filament. Then send it to the printer. The app asks you to confirm before it starts a print.

3. Print alerts

In Settings, turn on Background print alerts to be told when a saved printer finishes, fails or goes offline while the app is closed. Android asks for notification permission only at that point.

4. Back up your printers

In Settings, choose Back up printers, set a passphrase, and save the file wherever you like. Restore printers reads it back. We cannot recover the passphrase, so keep it somewhere safe.

Questions

Do I need an account?

No. There is no Nozzle It All account.

Does my model go to a server?

No. Slicing happens on your phone. Only model searches and downloads in Discover go to MyMiniFactory. See the privacy policy.

Why does the app say a printer is "not verified on real hardware"?

Because we have not run that printer type on a real printer yet. See Printers.

Can I use it from a web browser or a computer?

Not yet. A Linux desktop app and a web app are planned. The web app will need an engine that you run yourself, described on its page. Instructions for setting up that engine will be published here when it exists.
