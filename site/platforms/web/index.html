Platforms / Web app

The web app Planned

The web app is planned. It does not exist yet, so there is nothing to open or install. This page explains how it is designed, so you know what to expect.

No Nozzle account. No Nozzle cloud. The web app is an interface. The slicing and the printer connections happen in an engine that you run.

How it is designed to work

The web app is a progressive web app: a page you can install from the browser. It talks to a Nozzle Engine Service, which does the heavy lifting. You get one in either of two ways:

  • the Linux desktop app (planned first), which runs the engine on your own computer, or
  • a self-hosted engine service you run on your own machine or server, as a container or a system service.

We do not run a shared service for other people, and the plan does not include one.

What needs the engine

These all need the engine service, because a web page cannot do them on its own:

  • slicing a model into G-code,
  • connecting to Bambu Lab and PrusaLink printers,
  • camera streams,
  • finding printers on your network.

What works without it

With no engine reachable, the web app is limited to opening, editing and preparing projects, and to projects it has cached for offline use. It cannot slice or reach a printer by itself.

Why a web page cannot reach your printers directly

Most printers on a home network speak plain HTTP or other local protocols. A web page served over HTTPS is blocked by browsers from calling them (mixed-content rules), browsers are also tightening access to devices on your local network, and some printers, such as Bambu Lab, use protocols a browser cannot use at all. The engine service sits between the two. That is a browser limit, and it is the main reason the web app is built this way.

Status

The web app comes after the Linux desktop app and before the Windows desktop app. When it exists, it will be at its own address and this page will say so, with a real link. Until then, follow progress on GitHub.
